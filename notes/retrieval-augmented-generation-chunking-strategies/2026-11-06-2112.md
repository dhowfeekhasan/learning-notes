## TIL: RAG Chunking Strategies Determine Retrieval Quality

Naive fixed-size chunking (e.g., 512 tokens with overlap) often splits semantic concepts across boundaries, forcing the retriever to fetch incomplete context. **Semantic chunking** uses embedding similarity to split text only when topic shifts occur, preserving conceptual cohesion. **Hierarchical chunking** indexes both small "child" chunks (for precision) and large "parent" chunks (for context), retrieving the parent when a child matches. **Agentic chunking** employs an LLM to logically segment documents (e.g., by markdown headers or logical arguments), maximizing semantic density per token.

The optimal strategy depends on data structure: semantic for unstructured prose, hierarchical for technical manuals requiring broad context, and agentic for complex legal/financial docs where structure implies meaning. Overlap remains critical for fixed/semantic methods to mitigate boundary loss.

```python
# Semantic Chunking with LangChain (requires: langchain, langchain-experimental, openai)
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai.embeddings import OpenAIEmbeddings

text = "Quantum computing uses qubits. Qubits enable superposition. Classical computers use bits. Bits are binary."

splitter = SemanticChunker(
    OpenAIEmbeddings(), 
    breakpoint_threshold_type="percentile", # Split at top % dissimilarity
    breakpoint_threshold_amount=95
)

chunks = splitter.create_documents([text])
for i, chunk in enumerate(chunks):
    print(f"Chunk {i+1}: {chunk.page_content.strip()}")
```
