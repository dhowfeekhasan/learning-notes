# TIL: Prompt Caching & Token Cost Control

Many LLM APIs (Anthropic, OpenAI, Google) support **automatic prompt caching**. When a request shares an identical prefix (system prompt, few-shot examples, large context) with a recent request, the provider reuses the computed attention keys/values (KV cache) instead of recomputing them. This slashes latency (often >50%) and reduces input token costs significantly (typically 50–90% discount on cached tokens).

**Control strategy:** Structure prompts so the **largest, most static blocks come first**. Place system instructions, RAG context, and few-shot examples *before* dynamic user input. Ensure exact character-for-character matches (whitespace, formatting, model parameters like `temperature`) to trigger cache hits. Avoid prepending variable timestamps or request IDs to the static prefix.

**Monitoring:** Check response headers/metadata (`x-cache-hit`, `usage.prompt_tokens_details.cached_tokens`) to verify hit rates. A low hit rate usually indicates non-deterministic prompt construction or excessive cache TTL expiration (typically 5–60 mins of inactivity).

```python
import openai, os
client = openai.OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

STATIC_PREFIX = """System: You are a concise analyst.
Context: [Large 50k token document pasted here verbatim]
Examples:
Q: Summary? A: [Example summary]"""

# Request 1: Populates cache (Full price)
r1 = client.chat.completions.create(
    model="gpt-4o", messages=[
        {"role": "system", "content": STATIC_PREFIX},
        {"role": "user", "content": "Analyze section 1."}
    ])
print(f"Run 1 Cached: {r1.usage.prompt_tokens_details.cached_tokens}") # 0

# Request 2: Reuses prefix (Discounted price)
r2 = client.chat.completions.create(
    model="gpt-4o", messages=[
        {"role": "system", "content": STATIC_PREFIX}, # Exact match
        {"role": "user", "content": "Analyze section 2."}
    ])
print(f"Run 2 Cached: {r2.usage.prompt_tokens_details.cached_tokens}") # > 0
```
