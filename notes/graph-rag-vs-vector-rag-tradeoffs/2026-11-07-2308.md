## TIL: Graph RAG vs Vector RAG Tradeoffs

**Vector RAG** excels at semantic similarity search—finding "needles in haystacks" via embedding cosine similarity. It scales horizontally, requires no schema, and handles unstructured text natively. However, it struggles with multi-hop reasoning, entity disambiguation, and global questions ("What are all themes across these documents?") because chunks lack explicit relationships.

**Graph RAG** builds a knowledge graph (entities + relationships) from documents, then retrieves via graph traversal or community summaries. It enables multi-hop reasoning, precise entity resolution, and holistic summarization. Costs: expensive upfront extraction (LLM calls per doc), schema design complexity, and slower query latency for deep traversals. Best for dense, interconnected domains (legal, biomedical, codebases).

**Hybrid approach** wins in production: vector search for candidate retrieval, graph expansion for context enrichment. Use vector for "find relevant chunks," graph for "explain how X relates to Y."

```python
# Minimal hybrid: vector retrieve -> graph expand (Neo4j + sentence-transformers)
from neo4j import GraphDatabase
from sentence_transformers import SentenceTransformer

driver = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "password"))
model = SentenceTransformer("all-MiniLM-L6-v2")

def hybrid_search(question, k=5, hops=1):
    q_emb = model.encode(question).tolist()
    with driver.session() as session:
        # 1. Vector ANN search (requires Neo4j 5.11+ vector index)
        vec_rows = session.run("""
            CALL db.index.vector.queryNodes('chunk_embeddings', $k, $q_emb)
            YIELD node AS chunk, score
            RETURN chunk.id AS cid, chunk.text AS text, score
        """, k=k, q_emb=q_emb).data()
        cids = [r["cid"] for r in vec_rows]
        # 2. Graph expansion: 1-hop neighbors of retrieved chunks
        graph_rows = session.run("""
            MATCH (c:Chunk)<-[:HAS_CHUNK]-(d:Document)-[:HAS_CHUNK]->(c2:Chunk)
            WHERE c.id IN $cids
            RETURN DISTINCT c2.id AS cid, c2.text AS text
        """, cids=cids).data()
    return vec_rows + graph_rows

print(hybrid_search("How does Graph RAG handle multi-hop reasoning?"))
```
